## فعّل تسجيل الدخول بجوجل (اختياري — الموقع يعمل بدونه)

> الموقع يعمل بالكامل لزائر جديد **بدون** Firebase: ١٥٩٥ رابطاً والبحث والأداة
> كلهم يعملون. Firebase يضيف فقط: تسجيل الدخول، ولوحة التحكم، والمزامنة.

1. افتح <https://console.firebase.google.com> ← Add project
2. **Authentication** ← Sign-in method ← **Google** ← فعّل
3. **Authorized domains** ← أضف `monstorjohan-png.github.io`
4. **Project settings** ← General ← SDK setup and configuration ← انسخ القيم
5. افتح `assets/js/config.js` واستبدل القيم:

```js
firebase: {
  apiKey: "القيمة_الحقيقية",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
}
```

6. **Firestore Database** ← Create database ← Production mode
7. انشر قواعد الأمان:

```powershell
npm install -g firebase-tools
firebase login
firebase init
firebase deploy --only firestore:rules
```

8. **اجعل نفسك مشرفاً:**
   - افتح **Authentication** ← Users ← اضغط على حسابك ← انسخ **UID**
   - في Firestore أنشئ مجموعة `admins` وأضف مستنداً باسم هذا الـ UID
9. ضع الـ UID في `config.js`:

```js
adminUids: ["UID_الخاص_بك"]
```

10. أعد النشر على Netlify أو Vercel

## قيود يجب معرفتها

### ١. التحديث يدوي وليس تلقائي

الموقع **لا يبحث في الإنترنت بنفسه** ولا يضيف مواقع من تلقاء نفسه. التحديث يتم بطريقتين:
- من لوحة التحكم: تضيف أو تعدّل أو تحذف الروابط بنفسك
- من الزوار: يرسلون روابطهم وتُراجعها قبل النشر

البحث التلقائي عن مواقع جديدة يتطلب خدمة خارجية مدفوعة أو نظاماً معقداً، وهذا غير ممكن مجاناً.

### ٢. أداة التحميل لا تحمّل من موقعك — وده مثبت بالاختبار

هذه أهم نقطة يجب فهمها بوضوح، وليست رأياً:

**لماذا لا يمكن لموقع ثابت أن يحمّل فيديو؟**
التحويل يحتاج برنامجاً اسمه `yt-dlp` يعمل على **خادم**. أي موقع مبني بـ
HTML و JavaScript فقط لا يستطيع تشغيله. قيد تقني في المتصفح نفسه، لا نقص في الموقع.

**الدليل العملي (تم فحصه حيّاً):**

```
$ node tools/test-cobalt-api.js
POST https://api.cobalt.tools/  →  HTTP 400
{"error":{"code":"error.api.auth.jwt.missing"}}
```

حتى واجهة Cobalt نفسها — وهي الأفضل في العالم لهذا الغرض — **ترفض أي طلب بلا مفتاح**.
فلا يوجد أي موقع مجاني ثابت يمكنه التحميل نيابةً عنك.

**ما تفعله الأداة فعلاً:**
1. تتحقق من الرابط والمنصة (٦ منصات مدعومة)
2. **تفحص صحة ٤ خدمات تحميل حيّاً** وتعرض للمستخدم أيها يعمل الآن
3. تعطي خطوات مرقّمة وزر نسخ بضغطة واحدة

الخدمات المفحوصة حيّاً:

| الخدمة | الحالة | الحكم |
|---|---|---|
| **Cobalt** | 200 | ★ موصى به — مفتوح المصدر بلا إعلانات |
| 9Convert | 200 | احتياطي — يحتوي إعلانات |
| TikMate | 200 | احتياطي — يحتوي إعلانات |
| YT1s | 200 | احتياطي — يحتوي إعلانات |

> **`loader.to` حُذف** — فحصناه حيّاً فوجدناه يحوّل إلى شبكة إعلانات تعرض أشرطة
> تحميل وهمية وتطلب تثبيت برامج. لا نوجّه أحداً إلى مواقع كهذه.

**إن أردت تحميلاً حقيقياً بلا حدود:** شغّل نسخة Cobalt خاصة على خادم صغير
(نحو ٤ دولارات شهرياً على DigitalOcean) ثم ضع رابطها في `config.js` في
`download.selfHosted`، وستظهر تلقائياً كخيار أول في الأداة.

المنصات المدعومة: **YouTube · TikTok · X/Twitter · SoundCloud** (فيديو وصوت)
و **Facebook · Instagram** (فيديو فقط — استخراج الصوت غير مدعوم فيها).

#### تفعيل التحميل الحقيقي (الطريقة الوحيدة الكاملة)

```bash

  --name cobalt \
  -e API_URL=http://localhost:9000/ \
```

### ٣. فحص الروابط آلي وليس كاملاً

يفحص الموقع ١٥ نمطاً خطيراً تلقائياً:
ملفات التنفيذ، روابط javascript و data، عناوين IP، روابط localhost، مختصرات الروابط، بيانات الدخول في الرابط، المسافات، البروتوكولات الخطرة.

لكنه **لا يفحص محتوى الموقع نفسه**. المراجعة اليدوية قبل النشر ضرورية.

### ٤. بعض الروابط قد تخالف قوانين محلية

روابط مثل `Libgen` و `Kutub` متضمنة **مع تحذير واضح** لأنها قد تخالف قوانين التوزيع في بعض الدول. استخدمها على مسؤوليتك.

## 🔒 حالة الأمان — بصراحة تامة

على GitHub Pages، الترويسات المفحوصة بـ `node tools/check-headers.js`:

| الترويسة | الحالة | لماذا |
|---|---|---|
| HTTPS | ✅ يعمل | إجباري على Pages |
| HSTS | ✅ موجود | تضيفه Pages تلقائياً |
| **CSP** | ❌ غائبة | Pages لا يسمح بترويسات مخصصة |
| X-Frame-Options | ❌ غائبة | نفس السبب |
| X-Content-Type-Options | ❌ غائبة | نفس السبب |
| Referrer-Policy | ❌ غائبة | نفس السبب |
| Permissions-Policy | ❌ غائبة | نفس السبب |

**هذا لا يعني أن الموقع مكشوف.** ترويسات HTTP دفاع مساند، أما حماية البيانات فـ:

1. **Firestore Security Rules** — ملف `firestore.rules` (٣٠٧ سطراً) يمنع أي زائر
   من تعديل أو حذف الروابط، ويجعل `admins/{uid}` غير قابل للإنشاء من المتصفح.
   اختُبرت على محاكي Firebase: **٥٧/٥٧** لقواعد Firestore و **٢٠/٢٠** لقواعد Storage.
2. **Firebase Auth** — تسجيل الدخول بالهوية هو ما يحمي لوحة التحكم فعلياً،
   لا robots.txt ولا أي ترويسة.

**إن أردت ترويسات الأمان أيضاً:** انشر نفس المجلد على
<https://app.netlify.com/drop> (اسحب وأفلت) في دقيقة — ملفات `netlify.toml`
و `vercel.json` مضمنة وستُطبَّق تلقائياً.

### ⚠️ المستودع عام — ما الذي يعني ذلك؟

GitHub Pages يحتاج مستودعاً عاماً على الخطة المجانية، وهذا مقصود. المعنى العملي:
- روابط الموقع والقواعد الأمنية ظاهرة للجميع — وهذا طبيعي في المشاريع المفتوحة
- **لا تضع مفاتيح Firebase الحقيقية في `config.js` أبداً.** مفتاح `apiKey` في
  Firebase آمن للنشر العام **بحد ذاته** — الأمان يأتي من القواعد لا من إخفاء المفتاح
- لا تضع أبداً: مفاتيح Stripe، أو كلمات مرور بريد، أو أي بيانات شخصية

**الحل المطبَّق في `sw.js`:**
- نقدّم النسخة المحفوظة **فوراً** (سرعة فتح)
- ونحدّثها من الشبكة **في الخلفية** في نفس اللحظة
- النسخة الحديثة تصل الكاش تلقائياً مهما طال عمر النسخة القديمة
- `index.html` يحمل `?v=` على كل الملفات الأساسية لكسر كاش المتصفح

### 🚨 العلّة التي كادت تُسقِط الموقع — وحارسها

ظهر خطأ خطير: **الموقع كان يعرض 525 رابطاً بدل 569**، ومعه روابط قرصنة
محذوفة. وأخطر من ذلك: **كل الفحوص كانت تمرّ بنجاح**. الأرقام متطابقة،
و`data.js` الصحيح كان موجوداً على الخادم.

**لماذا نجحت كل الفحوص؟** لأن الفحص يقارن المتصفح برقم الإصدار.
وإصدار الصفحة وإصدار الكود القديم يحملان **الرقم نفسه**. لا فرق مرئي بين
«صحيح» و«كاذب» ما دام الرقمان متساويين — وهذا جوهر العلّة.

**السبب الجذري: خطأ بشري في سطر واحد.**
```js
// الخاطئ — APP_CONFIG.version غير موجود أصلاً
const sameVersion = cached.ver === APP_CONFIG.version;   // undefined === undefined → true
// الصحيح
const sameVersion = cached.ver === APP_CONFIG.cache.version;
```
كل كاش قديم بلا `ver` كان يمرّ الفحص. ومعه `persistCache()` كانت تعيد
كتابة الكاش **بلا** `ver` في كل زيارة — فتجدد السموم كل مرة.

**والمشكلة الثانية: عامل الخدمة يخزّن خطأً.**
`caches.addAll()` يجلب الملفات لحظة التثبيت. لو كان النشر لم يكتمل على
GitHub Pages بعد، خزّن النسخة **القديمة** تحت اسم يحمل الرقم الجديد.
فالاسم يقول `1.4.4` والمحتوى قديم — ولا شيء يكشف ذلك.

### 🛡️ الحارس: `guardDataIntegrity` في `app.js`

الحل: **لا نثق في الكاش، نتحقق من الشبكة.**

1. `config.js` يحمل `expectedLinks: 569` —-truth واحدة من الخادم.
2. عند الإقلاع: إن اختلف `LINKS.length` عن 569 → الكاش يكذب.
3. نسأل **الشبكة مباشرة** باستعلام عشوائي (`?probe=`) حتى لا يخدمه الكاش.
4. إن أعطت الشبكة العدد الصحيح: نلغي عامل الخدمة، نحذف كل الكاشات، نعيد التحميل.
5. `sessionStorage` يمنع تكرار المحاولة — **بلا حلقة إعادة تحميل لا نهائية**.

الحارس وحده كشف ما عجز عنه كل شيء آخر، لأن أرقام الإصدار تعجز عن التمييز.

**البرهان** — خادم فيه عامل خدمة **كاذب عمداً** (شبكة 569 / كاش 525):

| القياس | قبل | بعد الحارس |

| روابط القرصنة | 5 | **0** |
| روابط `example.com` الوهمية | 525 | **0** |
| أخطاء الطرفية | 0 | **0** |

الكاذب أُزيل وعُوِّض `sw.js` الحقيقي. الأداة: `node tools/liar-server.js`

## المدققات

شغّل **المدقق الشامل** قبل أي نشر:

```bash
node tools/audit-all.js
```

يشغّل ثلاث مدققات ويخرج ملخصاً واحداً:

| المدقق | ما يفحصه |
|---|---|
| `tools/audit-data.js` | صيغة الرابط (https فقط)، التكرار، الأوصاف الفارغة أو التالفة، الأقسام غير المعروفة، اللغات، الأنواع، الحروف الصينية |
| `tools/audit-encoding.js` | محارف الاستبدال التالفة (U+FFFD)، حروف صينية/كورية/يابانية متسللة، كلمات لاتينية ملتصقة بحروف عربية (التلف البنيوي) |
| `tools/audit-inline-scripts.js` | تركيب كل سكربت مضمّن داخل HTML عبر `node --check` |

النتيجة المطلوبة: `النتيجة: كل المدققات نجحت ✓`

كل مدقق **يُنهي التنفيذ برمز خطأ `exit 1`** عند وجود مشكلة، فيمكن ربطها بأي نظام CI/CD تلقائي.
