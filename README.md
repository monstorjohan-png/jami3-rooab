## النشر المجاني الدائم — ٣ خطوات

### الخطوة ١ — ارفع المشروع على GitHub

```powershell
cd jami3-rooab
git init
git add .
git commit -m "جامع الروابط - الإصدار الأول"
```

أنشئ مستودعاً فارغاً على <https://github.com> ثم:

```powershell
git remote add origin https://github.com/<اسمك>/<المستودع>.git
git push -u origin main
```

### الخطوة ٢ — انشر على منصة مجانية

اختر أي واحدة منها — كلها مجانية وتعطي دوميناً دائماً:

- **Netlify** — <https://app.netlify.com> ← Add new site ← Import an existing project ← اختر المستودع
- **Vercel** — <https://vercel.com/new> ← استورد المستودع ← Deploy
- **Cloudflare Pages** — <https://dash.cloudflare.com> ← Workers & Pages ← Create ← Pages ← اربط GitHub

الدومين سيكون مثل: `اسم-موقعك.netlify.app`

هذه المنصات تقرأ ملفات `netlify.toml` و `vercel.json` وتطبّق ترويسات الحماية تلقائياً.

> **خطوة إلزامية بعد النشر:** افتح `robots.txt` و `sitemap.xml` واستبدل
> `example.com` بنطاقك الحقيقي في السطرين. بدونها لن تظهر موقعك في نتائج البحث.
>
> ```powershell
> # مثال على PowerShell
> $d = "اسم-موقعك.netlify.app"
> (Get-Content robots.txt -Raw).Replace("example.com", $d) | Set-Content robots.txt -Encoding utf8
> (Get-Content sitemap.xml -Raw).Replace("example.com", $d) | Set-Content sitemap.xml -Encoding utf8
> ```

### الخطوة ٣ — فعّل تسجيل الدخول بجوجل

1. افتح <https://console.firebase.google.com> ← Add project
2. **Authentication** ← Sign-in method ← **Google** ← فعّل
3. **Authorized domains** ← أضف دومينك الذي اخترته في الخطوة ٢
4. **Project settings** ← General ← SDK setup and configuration ← انسخ القيم
5. افتح `assets/js/config.js` واستبدل القيم:

```js
firebase: {
  apiKey: "القيمة_الحقيقية",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
}
```

6. **Firestore Database** ← Create database ← Production mode
7. انشر قواعد الأمان:

```powershell
npm install -g firebase-tools
firebase login
firebase init
firebase deploy --only firestore:rules
```

8. **اجعل نفسك مشرفاً:**
   - افتح **Authentication** ← Users ← اضغط على حسابك ← انسخ **UID**
   - في Firestore أنشئ مجموعة `admins` وأضف مستنداً باسم هذا الـ UID
9. ضع الـ UID في `config.js`:

```js
adminUids: ["UID_الخاص_بك"]
```

10. أعد النشر على Netlify أو Vercel

## قيود يجب معرفتها

### ١. التحديث يدوي وليس تلقائي

الموقع **لا يبحث في الإنترنت بنفسه** ولا يضيف مواقع من تلقاء نفسه. التحديث يتم بطريقتين:
- من لوحة التحكم: تضيف أو تعدّل أو تحذف الروابط بنفسك
- من الزوار: يرسلون روابطهم وتُراجعها قبل النشر

البحث التلقائي عن مواقع جديدة يتطلب خدمة خارجية مدفوعة أو نظاماً معقداً، وهذا غير ممكن مجاناً.

### ٢. أداة التحميل توجّه فقط

الموقع **لا يستضيف أي ملفات ولا يقوم بتحويلها**. ما يحدث فعلياً:
1. يتحقق من صحة الرابط والمنصة
2. يفتح لك أداة خارجية مفتوحة المصدر
3. التحميل يتم على جهازك أنت مباشرة

التحويل الحقيقي (دمج الصوت مع الفيديو) يحتاج خادماً بارداً مع أدوات مثل `yt-dlp` — وهذا مكلف ومستحيل مجاناً.

المنصات المدعومة مجاناً: **YouTube و TikTok و Twitter/X و SoundCloud**

### ٣. فحص الروابط آلي وليس كاملاً

يفحص الموقع ١٥ نمطاً خطيراً تلقائياً:
ملفات التنفيذ، روابط javascript و data، عناوين IP، روابط localhost، مختصرات الروابط، بيانات الدخول في الرابط، المسافات، البروتوكولات الخطرة.

لكنه **لا يفحص محتوى الموقع نفسه**. المراجعة اليدوية قبل النشر ضرورية.

### ٤. بعض الروابط قد تخالف قوانين محلية

روابط مثل `Libgen` و `Kutub` متضمنة **مع تحذير واضح** لأنها قد تخالف قوانين التوزيع في بعض الدول. استخدمها على مسؤوليتك.

## المدققات

شغّل **المدقق الشامل** قبل أي نشر:

```bash
node tools/audit-all.js
```

يشغّل ثلاث مدققات ويخرج ملخصاً واحداً:

| المدقق | ما يفحصه |
|---|---|
| `tools/audit-data.js` | صيغة الرابط (https فقط)، التكرار، الأوصاف الفارغة أو التالفة، الأقسام غير المعروفة، اللغات، الأنواع، الحروف الصينية |
| `tools/audit-encoding.js` | محارف الاستبدال التالفة (U+FFFD)، حروف صينية/كورية/يابانية متسللة، كلمات لاتينية ملتصقة بحروف عربية (التلف البنيوي) |
| `tools/audit-inline-scripts.js` | تركيب كل سكربت مضمّن داخل HTML عبر `node --check` |

النتيجة المطلوبة: `النتيجة: كل المدققات نجحت ✓`

كل مدقق **يُنهي التنفيذ برمز خطأ `exit 1`** عند وجود مشكلة، فيمكن ربطها بأي نظام CI/CD تلقائي.

### اختبار البوابة نفسها

```bash
node tools/test-audit-gate.js
```

يحقن عيوباً متعمدة (محرف تالف، حرف صيني، كلمة ملتصقة) ويتأكد أن المدقق الشامل
**يرفضها**، ثم يستعيد الملف ويتأكد أنه **يقبل** المشروع السليم. هذا يثبت أن البوابة
تعمل بالاتجاهين — لا تفشل دائماً ولا تمرّر دائماً. النتيجة المطلوبة: `٥ / ٥`.
